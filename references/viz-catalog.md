# 표준 시각화 카탈로그 v1.1 (2026-10-25)

> 리스닝마인드 데이터를 시각화하는 차트 레퍼런스입니다.
> 에이전트는 차트를 직접 고르거나 SVG를 손으로 그리지 않는다. 데이터를 스펙으로 넘기면 코드가 데이터 모양을 읽어 차트를 고르고 그린다.
> 코드: `lib/viz.py` (CATALOG·select·render·check_html) · 명령 `scripts/viz.py` · 견본 `lib/viz_samples.py` — 모두 이 스킬 폴더 안에 있다
> 원칙: 외부 차트 라이브러리·캔버스 없이 inline SVG · 코드가 데이터 모양으로 차트를 고른다 · 문장 속 숫자는 차트에 있는 값과 계산식에서만

## 1. 에이전트 절차 — 데이터 확인 → 선택 → 렌더 → 검사

**한 번에**: `python3 viz.py auto <데이터.csv|json> --unit <단위> --period <기간> [--intent …] [--compare]` — 파일을 읽어 프로파일 → 추천 상위 3(점수·이유) → 1위 렌더 + 표 쌍둥이 → 페이지(`<데이터>.viz.html`)까지 만든다. `--compare`는 상위 3을 모두 그려 사람이 고르게 한다. 리포트 코드에서는 `viz.auto(spec)`. 아래 1~4는 이 한 번 호출이 하는 일을 나눈 것이다.

1. **데이터를 확인한다** — 차트에 넣을 값을 저장된 데이터에서 읽어 `viz-data/v1` 스펙(아래 §2)으로 만든다. 값을 손으로 옮겨 적지 않는다.
2. **선택한다** — `python3 viz.py select <spec.json>`. 결과의 `chart`·`reason`을 그대로 쓴다. 함께 나오는 `ranked`(상위 3 · 점수 · 이유)는 사람이 다른 차트를 고를 때의 근거이고, `hints`는 데이터에서 읽은 제안(값이 1,000배 퍼짐 → 로그 눈금 · 한 항목이 절반 이상 → 강조 · 이름이 순서 범주 · 빠진 달)이다. 점수는 순서를 정하는 데만 쓰고 1위는 언제나 `chart`와 같다.
   보여 주려는 의도가 분명하면 `--intent`(§3)를 준다. 의도의 차트가 데이터 조건을 못 채우면 기본 선택으로 돌아가고 `intent_note`에 이유가 남는다.
3. **렌더한다** — `python3 viz.py render <spec.json> --out <조각.html>` 또는 코드에서 `viz.render(spec)`. 결과는 `<figure class="viz" data-viz=…>` 조각이다.
   외부 전달물은 `--with-table`(`viz.render(spec, with_table=True)`)로 같은 데이터의 접힌 표를 붙인다 — 값을 색·길이로만 읽지 않게 하고 숫자 대조의 근거가 된다.
   차트를 지정(`--chart`)할 수는 있지만 조건을 못 채우면 멈춘다(종료 코드 2) — 조건을 바꾸지 말고 데이터를 다시 본다.
4. **검사한다** — `python3 viz.py check <산출물.html>`. 카탈로그 밖 차트·단위/기간 누락·캔버스·차트 라이브러리는 실패(종료 코드 11).
   표준 차트가 하나도 없는 산출물은 `legacy`(이 카탈로그 이전에 만든 페이지)로 적는다.

- 단위(`unit`)·기간(`period`)이 없으면 렌더하지 않는다. 차트 **위 헤더**에 제목 → 부제(단위·기간·「전체 K개 중 N개」·기준월·수집·채널) → 발견 한 줄(§2c)이 자동으로 붙고, 캡션(아래)에는 미반환·출처만 남는다.
- 행·관계가 모두 비면 차트 대신 문장으로 쓴다. 완성도(`completeness`) 0.5 미만이면 의도와 관계없이 표만 쓸 수 있다.
- 갤러리: `python3 viz.py gallery --out <파일.html>` — 견본 데이터로 모든 차트를 그린다(리뷰·디자인 확인용).

## 2. 스펙 — viz-data/v1

```json
{
  "title": "진입 상황별 진입 검색 비중", "unit": "건/월", "period": "2025-09~2026-08", "source": "분석 2026-09-27",
  "intent": "compare",
  "fields": {"dims": ["상황"], "measures": [{"field": "검색량", "kind": "count"}], "time": null},
  "labels": {"검색량": "월 검색량"},
  "rows": [{"상황": "부모님 선물", "검색량": 12376}],
  "edges": [{"source": "로봇청소기", "target": "로봇청소기 추천", "value": 44}],
  "paths": [["집들이 선물", "이사 선물", "이사 선물 추천"]],
  "options": {"top_n": 12, "x_threshold": 0, "y_threshold": 0.5, "quadrant_labels": {"tr": "…"}, "forecast_from": "2026-03", "band": ["하한", "상한"], "order": ["10대", "20대"], "whole": true, "months": 24,
              "seed": "이사 선물", "emphasis": ["브랜드 A"], "log_y": true, "axis_ends": {"x": ["왼쪽 뜻", "오른쪽 뜻"]}, "scale": "steps", "baseline": 1.0, "highlight": {"above": 2.0}, "badge": "구분",
              "finding": "auto", "hero": "월 진입 검색량", "spark": {"월 진입 검색량": [281000, 283500]},
              "title_mode": "action", "takeaway": "결론 한 줄(숫자는 차트에 있는 것만)", "label_points": "all", "bridge": {"start": "2025-08", "end": "2026-08"}},
  "exhibit": "그림 1", "footnotes": ["각주 1", "각주 2"],
  "completeness": 1.0
}
```

- `fields`를 생략하면 코드가 추정한다: `YYYY-MM` 값 → 시간 축, 숫자 → 측정값, 나머지 → 범주. 의도와 다르게 추정되면 `fields`를 적는다.
- 측정값 종류(`kind`): `count`(건) · `share`(비율 0~1) · `change`(증감 비율, 0.12 = +12%) · `index`(1.0 = 기준) · `score`(0~100) · `rank`(1 = 1위) · `value`.
  이름에 순위·비중·증감·점수·지수가 들어가면 그 종류로 추정한다.
- 시간 축 값이 6개 미만이면 순서 있는 범주로 본다(예: 2023·2024·2025 → 묶음 막대).
- 범주 이름이 연령대(10대 · 20대 초반 · 50대 이상)·구간(20~24)·단계·월처럼 보이면(80% 이상) **순서 있는 범주**로 보고, 열·막대 순서를 값 크기가 아니라 그 순서(자연 정렬)로 둔다. `options.order`로 직접 줄 수도 있다.
- 프로파일은 측정값마다 `stats`(최소·최대 · 양수 최대/최소 배수 · 최대값의 비중)를 계산해 로그 눈금·강조 제안에 쓴다.
- 칸 값이 숫자 목록이면 추이 칸(`fields.series`), `{조각: 비율}`이면 구성 칸(`fields.mix`)으로 본다 — 그래픽 표가 그린다.
- `paths`는 검색 경로(키워드 순서 목록)다. 같은 세션에서 이어진 검색이지 한 사람의 여정이 아니다.

## 2b. 값의 상태 — 값이 없는 칸을 구분한다

리스닝마인드 데이터는 '값 있음' 말고도 상태가 여럿이다. 상태마다 화면 모양과 문구가 다르고, 범례는 그 차트에 실제로 나온 상태만 칸과 같은 모양으로 그린다.

| 상태 | 뜻 | 스펙에 넣는 법 | 화면 |
|---|---|---|---|
| 값 | 측정한 값(0도 값이다) | 숫자 | 값 그대로 · 0은 길이 0 막대·옅은 칸 |
| 결측 | 응답에 그 칸이 없다(예: 네이버 값이 없는 달) | `null` | 점선 칸 '–' · 추이선은 끊김 · 막대는 '결측' |
| 조회 안 함 | 이번 분석이 그 칸을 부르지 않았다 — 분석 기록(요청 기록·품질 점검 기록)으로 판정 | `{"state": "not_queried"}` | 빗금 칸 '안 함' · 막대는 '조회 안 함' |
| 기저 미달 | 기준이 되는 값이 작아 비율·지수·증감률을 계산하지 않았다 | `{"state": "below_gate", "base": n}`(n = 실제 기저 값) | 회색 칸 '미달' · 막대는 '기저 n건 · 기준 미달' |
| 미반환 | 요청한 항목이 응답에 아예 없다 | 칸: `{"state": "not_returned"}` · 행 밖: 스펙 `not_returned: [...]` | 캡션 '미반환 n개: …' |
| 미완결 | 최신 월이 아직 채워지는 중 | `options.incomplete_from: "YYYY-MM"` | 추이선·스파크라인은 흐린 구간과 빈 점 · 성수기 지수 계산에서 뺀다 |

- 100% 구성 막대는 값 없는 조각이 있는 그룹을 그리지 않고 이유를 적는다(100%가 거짓이 되므로). 도넛은 값 없는 조각을 빼고 캡션에 적는다.
- 사분면 버블은 x·y 중 하나라도 값이 없는 항목을 그리지 않고 상태와 함께 목록으로 적는다.
- 캡션 정보: `base_month`(기준월 — 조회일보다 1개월 이상 늦다) · `collected_at`(검색결과 화면·경로·관계의 수집 시각 — 요청 시각이 아니다) · `channel`(구글·네이버·합계) · `market_note`(예: 한국 전용 — 성연령).

## 2c. 발견 한 줄 — 차트가 '보여 주는' 것에서 '말하는' 것으로 (2026-10-25 디자인 패스)

차트 위 헤더의 세 번째 줄은 **코드가 데이터에서 계산한 발견 문장**이다. LLM 이 자유 작문하지 않고, 차트별 고정 틀 하나에 숫자만 채운다. 바로 아래 '근거' 줄에 계산식을 적어 사람이 검산할 수 있게 한다.

| 차트 | 틀 | 근거 줄 |
|---|---|---|
| hbar(더할 수 있는 값) | `'1위' 하나가 전체의 P% — 상위 3개가 Q%` (항목 4개 이상일 때 뒷절) | 값 / 전체 = P% · 상위 3개 합 / 전체 = Q% · 값 있는 N개 기준 |
| hbar(점수·지수 등) | `1위 'A' 값 · 2위 'B' 값` | 값 큰 순 |
| diverging_bar | `가장 늘어난 'A' +x% · 가장 줄어든 'B' −y% · 늘어난 n개 / 줄어든 m개` | 값 있는 N개 중 늘어난·줄어든·0 개수 |
| line(계열 1개 또는 강조 1개) | 월 15개 이상·빠진 달 없음: `최근 3개월은 전년 같은 기간보다 ±x%` · 아니면 `최고 값(시점) · 최신 값(시점)` | 두 구간의 합과 나눗셈 · 실측 구간만(예측·미완결 제외) |
| donut | `가장 큰 조각 'A' P% — 상위 2개가 Q%` | 값 / 합 |
| scatter_quadrant | 사분면별 점 개수(사분면 이름이 있으면 그 이름으로) | 사분면 개수 = 그린 점 수 · 기준값 |
| funnel | `첫 단계 대비 마지막 단계 P% · 가장 크게 줄어든 단계 'A → B' (Q%만 남음)` | 두 나눗셈 |
| journey_map | `1→2단계 가장 많은 이동 'a → b' n개 경로` | n / 전체 경로 |
| treemap | 그룹이 있으면 `'G' 그룹이 전체의 P% — 상위 3개 그룹이 Q%` · 없으면 hbar 와 같음 | 값 / 전체 |
| knowledge_graph | `연결이 가장 많은 'X' (연결 n)` | 항목·연결 개수 |
| radar(계열 1개) | `'A' 가장 높은 축 'x' v · 가장 낮은 축 'y' v` | 축 개수 |
| waterfall | `'시작' v → '끝' v (±p%) · 가장 큰 기여 'A' ±n` | 시작 + (기여 …) = 끝 · 증감률 |
| 그 밖의 차트 · kpi | 없음(kpi 는 타일의 증감이 그 역할) | — |

- `options.finding`: 생략·`"auto"` = 위 틀 · `"off"` = 없음 · 문장을 직접 주면 그 문장을 쓴다. **직접 쓴 문장 속 숫자는 차트 글자에 있는 것만** 허용한다 — 없으면 렌더가 멈춘다.
- `check`는 발견 문장의 숫자 토큰(`28%`·`3개`·`+10%`…)이 차트 글자 또는 근거 줄에 모두 있는지 대조한다(없으면 BLOCK). 근거 줄의 합계·분모는 차트에 그려지지 않을 수 있으므로, 근거 줄이 검산의 출처다.
- 인과·권유 문장은 틀에 없다(규제 업권 가드레일). 제목·문장 검토가 있다면 발견 문장도 그 대상이다.

## 4. 카탈로그 — 차트 목록

`id`는 코드(`viz.CATALOG`)와 같아야 한다(테스트가 맞춰 본다). '데이터 조건'은 그 차트를 **쓸 수 있는** 범위이고, §5는 의도가 없을 때 **기본으로 고르는** 순서다 — 둘은 다를 수 있다(예: 계열 2~3개는 추이선과 스파크라인 묶음 모두 쓸 수 있고 기본은 추이선).

| id | 이름 | 영문 이름 | 답하는 질문 | 데이터 조건 | 인코딩 규칙 | 쓰임 예 |
|---|---|---|---|---|---|---|
| kpi | 지표 타일 | Stat tile | 핵심 값·점수·등급은 얼마인가 | 범주 없음 · 값 1~6개(행 1개) | 라벨 → 값(32px · `hero`로 지정한 값은 48px) → **증감**(바로 뒤에 오는 `change` 값이 ▲▼ + 그 값의 이름을 비교 기준으로) → **추이**(`spark`: 값 이름별 숫자 목록 — 스펙에 적힌 데이터만, 0 기준·마지막 값에 표식) · 값 종류에 맞는 숫자 형식 | 월 진입 검색량 + 전년 대비 + 12개월 추이 · 진단 점수 |
| hbar | 순위 가로 막대 | Horizontal bar chart | 어느 항목이 얼마나 큰가 | 범주 1개 × 값 · 항목 2개 이상 | 0 기준 · 큰 값부터 · 상위 12 + '기타'(검색량처럼 더할 수 있는 값만 기타로 합산) · 같은 값이면 이름순 · 가는 막대(행 30 · 막대 18) · 데이터 끝만 둥글게 · **강조**(`emphasis`): 이야기가 한 항목이면 그것만 색, 나머지 회색 — 지정이 없으면 **1위만 색** · 발견 = 집중도(§2c) | 상황별 검색량 · 카테고리 관심도 순위 |

## 5. 기본 선택 순서 (의도가 없을 때)

1. 행·연결·경로가 모두 없음 → 차트 없음(문장)
2. 완성도 0.5 미만 → table
3. 검색 경로가 있음 → 기준 검색어(`options.seed`)가 경로에 나오면 bidirectional_tree · 경로 5개 이상이고 3단계 이상이면 journey_map · 아니면 pair_bars
4. 연결이 있음 → 나무면 flow_tree · 항목 종류(`nodes[].class`)를 선언했으면 knowledge_graph · 나무가 아니고 값이 있으면 pair_bars · 값이 없으면 edge_table
5. 칸에 숫자 목록·구성이 있음 → table_graphic
6. 측정값이 순위이고 순서 있는 축이 3단계 이상 → bump
7. 시간 축(6개 이상) → 계열 3개 이하 line, 초과 spark_grid
8. 범주 없음 → kpi
9. 범주 1개 → `options.bridge`(시작·끝)를 선언했으면 waterfall · 반대 방향이라고 선언한(`options.opposite`) 같은 종류의 값 2개면 back_to_back · 값 2개 이상이면 scatter_quadrant(항목 4개 미만이면 table_graphic) · 증감·음수면 diverging_bar · 합 100% 2~5조각이면 donut · 순서 있는 단계 3~8개이고 단계마다 줄면 funnel · 이름이 길면(평균 14자 초과) table_graphic · 그 밖은 hbar
10. 범주 2개 × 값 1개 → 그룹마다 합 100%면 stacked_100 · 그룹 → 항목 계층(교차 칸의 절반 이하만 있음)이고 항목 12개 이상이면 treemap · 행 이름이 길거나(평균 10자 초과) 행이 20개 초과면 heat_table · 두 번째 범주 4개 이하면 grouped_bar · 그 밖은 heatmap
11. 그 밖 → table

## 6. 카탈로그에 없는 것

- **종류 없는 그물형 연결 그림** — 항목 종류(`nodes[].class`)가 없는 연결은 pair_bars(값 있음)·edge_table로 쓴다. 지식 그래프(2026-10-25 추가)는 종류가 선언돼 색이 뜻을 가질 때만 기본 선택이며, 배치는 난수 없이 고정한다.
- **레이더를 기본으로 고르지 않는다** — 모양이 축 순서의 산물이라 값 비교는 묶음 막대·히트맵이 더 정확하다. 의도 `profile`이나 지정으로만 쓰고 표 쌍둥이를 붙인다.
- 파이·이중 축·워드클라우드·선버스트·3D·게이지 — 넣지 않는다(각도·면적 판독 부정확 · 두 눈금 혼동 · 크기가 글자 길이의 산물).
- **카드형 목록**(질문·프롬프트 목록, 대상 카드, 광고 소재안) — 차트가 아니라 레이아웃이다. 카드 안의 작은 차트는 위 차트(spark·stacked_100 등)를 쓴다.
- 새 차트가 필요하면 코드(`CATALOG`·조건·렌더러·견본)와 이 표를 함께 바꾸고 테스트를 통과시킨다. 다른 코드 안에 따로 그리지 않는다.

## 6b. 색과 모양의 규칙 — 계산으로 지킨다 (2026-10-25 · 외부 차트 스킬 검토에서 채택)

- **팔레트는 눈으로 고르지 않는다.** 계열 색(`viz.PALETTE` 라이트·다크 6슬롯)과 사분면 분류 색은 `lib/palette_check.py`가
  명도 범위(라이트 0.43~0.77 · 다크 0.48~0.67) · 채도 하한 0.10 · 이웃 쌍 색각 분리 ΔE ≥ 8 · 정상 시각 ΔE ≥ 15 · 바탕 대비 3:1을 재고, 테스트가 지킨다.
  증가/감소 색은 바탕 대비 3:1만, 강조 바깥 회색(DIM)은 바탕 대비 1.4:1 이상(읽히되 물러남 — 우리 기준이며 인쇄·투사에서는 사람이 확인)을 잰다. 검사 바탕은 차트가 놓이는 패널색(라이트 #ffffff · 다크 #161a22)이다.
  이웃 기준은 막대·누적·추이선처럼 이웃끼리만 맞닿는 차트용이고, 산점도·버블처럼 모든 색이 맞닿는 차트는 **모든 쌍 기준으로 3색까지**(그래서 사분면 분류 색은 3색 + 회색).
  계열 색은 6개까지이고 7번째는 만들지 않는다 — '기타'(회색)로 묶거나 스몰 멀티플로 나눈다.
- **색은 의미를 나른다.** 이야기가 한 항목이면 범주 색을 다 칠하지 말고 **강조**(`emphasis`: 그 항목만 1번 색, 나머지 회색)를 쓴다.
  '자사'가 정해진 점유·브랜드 차트는 자사를 강조로 넘기는 것을 기본으로 한다. 강조 이름이 데이터에 없으면 강조 없이 그리고 캡션에 그 사실을 적는다(거짓 캡션 금지). 명목 범주(브랜드·상황)에 값 농도(큰 값일수록 진하게)를 칠하지 않는다 — 길이가 이미 값을 말한다.
- **칸 사이는 테두리가 아니라 2px 바탕 틈**(누적 조각·도넛 조각·표 속 구성 막대).
- **격자·축은 가는 실선 한 톤**, 점선은 기준선·예측·결측에만 쓴다(점선 격자는 '기준'으로 오독된다).
- **발산 색의 가운데는 회색**, 양극은 따뜻한 색 대 차가운 색(증감 막대의 증가 청록·감소 빨강).
- **모든 차트에 표 쌍둥이**(`--with-table`) — 접힌 표로 같은 값을 읽을 수 있어야 한다. 500행을 넘으면 요약 줄에 '전체 K행 중 500행'을 적는다. 표·그래픽 표·히트 표는 그 자체가 표라 붙이지 않는다.
- **마크 규격**(2026-10-25 디자인 패스): 막대는 가늘게(행 높이의 60%), 기준선 쪽은 각지고 **데이터 끝만 4px 둥글게**(`_bar`) · 추이선 2px · 끝점 표식 8px(바탕색 2px 테두리) ·
  추이선 눈금은 압축 표기(`_compact`: 1만·5천) · 직접 라벨은 끝점·극값·강조 계열만 · 헤더(제목 16 · 발견 14 · 본문 12 · 눈금 10.5 — `css_tokens` 의 `--viz-fs-*`)가 차트 위에, 캡션에는 출처·미반환만.
- **큰 숫자(KPI)에 고정폭 숫자(tabular-nums)를 쓰지 않는다** — 지금 렌더러는 어디에도 쓰지 않으며, 쓴다면 표·축 눈금에서만.
- 받지 않은 것: 차트 라이브러리(AntV·Recharts·D3·ggplot2) 코드 생성 — §7 inline SVG 규칙과 어긋난다 · 호버 툴팁 기본 탑재 — 정적·인쇄 산출물이라 SVG `<title>`로 대신한다 ·
  '범례 대신 직접 라벨' — 계열 2개 이상이면 범례를 두고 끝점·극값·강조 계열만 직접 라벨한다.

## 6c. 경영진 보고(컨설팅) 스타일 — 채택한 것과 뺀 것 (2026-10-25 · kgraph57/mckinsey-style-visualization-skill 검토)
